补测 B5 · 连接耗尽治理（max_connections 打满）

2026-05-18mysql 系列约 5 分钟阅读MySQL
补充实测对主线场景的边界补强，独立成篇可单独读。

一、问题背景

连接耗尽雪崩防护。当并发请求超过 MySQL max_connections，新连接报 Too many connections，请求大量失败，系统雪崩。需治理：连接池大小与 max_connections 匹配、耗尽时杀空闲连接 + 快速失败。

二、耗尽原理

并发连接 → MySQL Threads_connected → 达到 max_connections
                                        │ 超出
                                        └──> 新连接报 "Too many connections" → 请求失败 → 雪崩
  • Threads_connected：当前连接数。
  • max_connections：连接上限（默认 151）。
  • Threads_running：正在执行 SQL 的连接数（高并发瓶颈）。
  • 使用率 = Threads_connected / max_connections，超 80% 需警惕，近 100% 会雪崩。

三、演示接口

# 1. 调低 max_connections（模拟低上限）
curl "http://localhost:8080/conn/set-max?maxConn=60"

# 2. 连接状态（打满前）
curl "http://localhost:8080/conn/status"

# 3. 模拟耗尽（开启200连接不释放）
curl "http://localhost:8080/conn/exhaust?openCount=200"

# 4. 状态（耗尽后，使用率超100%）
curl "http://localhost:8080/conn/status"

# 5. 治理:杀空闲连接
curl "http://localhost:8080/conn/kill-idle?idleSeconds=1"

# 6. 治理:释放占用连接
curl "http://localhost:8080/conn/release"

# 7. 恢复 max_connections
curl "http://localhost:8080/conn/restore"

四、实测结果（max_connections 调低到 60）

环节 结果
打满前 Threads_connected=2，使用率 3.3%（健康）
模拟耗尽（开启200） opened=59、failed=141（60 个后报 Too many connections）、使用率 101.7%
释放占用连接 released=59、连接回落 2
恢复 max_connections=151

核心：max_connections=60 时开启 200 连接，前 59 个成功、后 141 个失败（连接耗尽），使用率超 100%。释放后连接回落，恢复健康。

五、治理方案

  1. 连接池大小匹配：连接池 max-size ≤ max_connections 且预留余量（如 80%），避免池把连接全占。
  2. 杀空闲连接：监控 Threads_connected，超阈值杀 idle（Sleep 长时间）连接，释放配额。
  3. 快速失败：连接池排队超时（connectionTimeout）快速失败，不无限等待造成雪崩。
  4. 连接复用：长连接复用 + 短事务，减少频繁建连。
  5. 监控告警：Threads_connected/max_connections 使用率超 80% 告警。
  6. 限流降级：入口限流，超阈值拒绝新请求，保护数据库。

六、要点速览

连接耗尽治理：并发超过 max_connections 时新连接报 Too many connections 雪崩。实测 max_connections=60 时开 200 连接，59 成功 141 失败，使用率超 100%。治理：连接池 ≤ max_connections 预留余量、耗尽杀空闲连接、快速失败、限流降级、监控 Threads_connected 使用率超 80% 告警。
