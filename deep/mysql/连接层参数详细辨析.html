MySQL 连接层参数详细辨析

2026-05-29mysql 系列约 9 分钟阅读MySQL
专题辨析只解决「连接层参数」这一个主题的逐项辨析。

基于 MySQL 5.7/8.0，线程缓存 thread_cache_size 参数，区分：连接、会话、线程、事务。 重要前提：MySQL 一个 TCP 连接 ≈ 一个会话(session)；一个会话绑定一个服务线程（1:1 模型），8.0 默认没有线程池（企业版才有线程池插件）。

1. Threads_connected

当前已经建立成功的 TCP 连接总数，会话数。 ✅ 只要 TCP 连接连上 MySQL 就算，不管有没有执行 SQL、有没有开启事务、有没有休眠 sleep。

  • 连接上来，sleep 休眠，没执行任何事务：算入 Threads_connected。
  • 正在跑事务：算。
  • 空闲长连接，挂在那里啥也不干：也算。
  • 仅仅尝试连接但是连接失败：不算（连接没建立成功）。

❗误区：不是正在执行事务的连接数。 想看正在运行的 SQL/事务，看： show processlist; Command=Query；或者 information_schema.innodb_trx（真正活跃事务）。 Threads_connected = 活跃执行 + 空闲 sleep 长连接总和。

2. Threads_created

MySQL 已经创建出来的服务线程总累计数（全局累加，不会归零）。

问题1：临时连接执行完断开，算不算？

算。流程（开启 thread_cache_size>0 线程缓存）：

  1. 客户端短连接：连接 MySQL → MySQL 新建线程 → Threads_created +1。
  2. SQL 执行完毕，客户端 close 断开连接。
  3. 如果线程缓存还有空位，线程不销毁，放入线程缓存池待命。
  4. 如果缓存池满，直接销毁这个线程。

👉 每一次真正新建一个操作系统线程，Threads_created 才 +1；从缓存里拿复用线程，不会 +1。

问题2：长连接是固定数值吗？

不是固定。

  • 长连接：客户端保持 TCP 不断，会话一直存在。
  • 如果长连接复用缓存线程：不会新增 Threads_created。
  • 如果重启、重连，就会新建线程，Threads_created 继续上涨。

Threads_created 是累计计数器，只增不减，不能看瞬时，要看上涨速率。 上涨很快：代表大量短连接，频繁创建销毁线程。

3. Aborted_connects

尝试连接 MySQL，但是连接建立阶段就失败的累计次数。 👉 是 TCP 握手、认证阶段失败，会话根本没创建成功！

触发场景：

  1. 密码错误。
  2. 不存在的账号。
  3. IP 不允许访问（授权 host 不匹配）。
  4. 达到 max_connections 最大连接数，MySQL 直接拒绝新连接。
  5. 网络问题，三次握手还没完成就中断。

✅ MySQL 拒绝连接 → Aborted_connects +1 ❌ 客户端连上之后，业务执行中主动断开，不会增加这个指标。

一句话：还没登录成功就挂了 → Aborted_connects。

4. Aborted_clients

连接已经建立登录成功，会话存在，后续异常断开，累计计数 +1。 已经登录成功之后的断开。

触发场景：

  1. 客户端程序异常崩溃、kill 进程，没执行 close，TCP 粗暴断开。
  2. wait_timeout / interactive_timeout 超时，MySQL 服务端主动关闭空闲会话（这个会算 Aborted_clients！）。
  3. 网络抖动，中间代理断开连接。
  4. 客户端执行完直接退出，没有正常关闭 mysql 会话。

❗误区纠正： 不单单只是客户端主动断开；MySQL 服务端因超时主动踢掉空闲 sleep 连接，也会 Aborted_clients +1。

区分两个 Aborted

指标 阶段 含义
Aborted_connects 连接认证阶段，登录失败 还没连上 MySQL，被拒绝/密码错
Aborted_clients 连接登录成功之后 会话已经建立，中途异常断开（客户端崩、服务端超时踢、网络断）

5. Thread_cache_hits

线程缓存命中次数，累计值。 MySQL 的线程缓存池（Thread Cache），缓存的是服务线程（操作系统线程），不是缓存连接，不是缓存会话。 参数 thread_cache_size=N：最多保留 N 个空闲 OS 线程放在缓存。

完整流程：

  1. 新客户端 TCP 连接进来。
  2. 如果线程缓存池里面有空闲线程：直接拿缓存好的 OS 线程来服务这个新连接 → Thread_cache_hits += 1，Threads_created 不会增加。
  3. 如果缓存池没有空闲线程：操作系统新建线程 → Threads_created += 1；连接结束后，如果缓存池没满，线程放回缓存。

Thread Cache 缓存的是OS 工作线程对象，避免频繁 pthread_create/pthread_destroy，减少 CPU 开销。

⚠️ 注意：

  • 缓存的是线程，不是 TCP 连接！TCP 连接断开，线程留在缓存等待下一个新 TCP 连接复用。
  • MySQL 8.0 默认 thread_cache_size=-1 自动自适应；5.7 默认 8。
  • 如果业务大量长连接，几乎不会复用线程缓存，Thread_cache_hits 几乎不增长，属于正常。

计算公式：线程缓存命中率

命中率 = Thread_cache_hits / (Thread_cache_hits + Threads_created)

命中率低，代表大量新建线程，大多是短连接业务。

汇总速查表

状态变量 含义 空闲 sleep 会话是否计入 事务无关说明
Threads_connected 当前已建立成功会话数(TCP 连上) ✅ 算 包含空闲无事务连接，不是运行中事务数量
Threads_created 累计创建 OS 工作线程数，只增不减 无，计数器 短连接频繁重连会快速上涨；从缓存复用线程不计数
Aborted_connects 登录/建立连接阶段失败 ❌ 连接都没建立 密码错误、max_connections 打满拒绝连接，属于这个
Aborted_clients 登录成功后会话异常断开 ✅ sleep 超时被 mysql 踢掉会 +1 客户端崩溃、超时、网络断都算
Thread_cache_hits 线程缓存命中次数，复用已有 OS 线程 无，计数器 缓存操作系统线程，减少创建销毁开销；长连接场景该值增长慢

生产排查小技巧

  1. Threads_connected 很高，但是 processlist 大量 Command=Sleep → 大量空闲长连接。
  2. Threads_created 持续快速上涨，Thread_cache_hits 低 → 大量短连接，考虑调大 thread_cache_size，或者程序加连接池。
  3. Aborted_connects 飙升：排查账号密码、IP 白名单、是否连接数打满。
  4. Aborted_clients 持续上涨：排查 wait_timeout 是否过小；应用是否没正常关闭连接、程序崩溃、代理超时。
  5. 看真实运行事务数量：select count(*) from information_schema.innodb_trx; 这个才是正在运行的事务，和 Threads_connected 完全两码事。

补充：企业版 MySQL Thread Pool 线程池，逻辑完全不一样，上面是默认 one-thread-per-connection 模型。
