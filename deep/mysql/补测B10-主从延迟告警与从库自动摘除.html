补测B10：主从延迟告警与从库自动摘除

2026-05-03mysql 系列约 5 分钟阅读MySQL
补充实测对主线场景的边界补强，独立成篇可单独读。

一、问题背景

读写分离下，从库复制延迟会导致读从库读到过期数据。延迟超阈值必须告警 + 自动把从库从读写分离摘除（读全部回主库），延迟恢复后再重新挂载。否则高并发下读到陈旧数据引发业务事故。

二、原理

主库 --复制--> 从库
                 │
   Seconds_Behind_Source 超过阈值
                 │
   ├── 告警 (ALERT)
   ├── 自动摘除 (EVICT)：从库从读写分离移除，读全部回主库
   └── 延迟恢复 → 重新挂载 (REMOUNT)
  • 模拟延迟：CHANGE REPLICATION SOURCE TO SOURCE_DELAY=N 人为设置复制延迟。
  • 检测：SHOW REPLICA STATUS 的 Seconds_Behind_Source。
  • 摘除：延迟 > 阈值 → 标记从库摘除，路由策略变为"读全部回主库"。

三、演示接口

# 1. 初始化读写分离
curl "http://localhost:8080/lag/init"

# 2. 模拟从库复制延迟 10s（会等延迟累计）
curl "http://localhost:8080/lag/simulate?delaySeconds=10"

# 3. 延迟检测 + 自动摘除（阈值5s，延迟>5触发）
curl "http://localhost:8080/lag/check?threshold=5"

# 4. 从库状态（应已摘除，读全部回主库）
curl "http://localhost:8080/lag/status"

# 5. 恢复从库（延迟归零，重新挂载）
curl "http://localhost:8080/lag/recover"

# 6. 恢复后检测（应重新挂载）
curl "http://localhost:8080/lag/check?threshold=5"

四、实测结果（模拟延迟10s，阈值5s）

环节 延迟 摘除 动作
init 0 false 正常
模拟延迟10s 7s false SOURCE_DELAY生效
检测(阈值5) 7 > 5 true ALERT+EVICT
状态 7 true 读全部回主库
恢复 0 false 重新挂载
恢复后检测 0 false NORMAL

核心闭环：延迟超阈值 → 告警 + 自动摘除从库（读全部回主库保一致）→ 延迟恢复 → 自动重新挂载。

五、工程要点

  1. 延迟监控：轮询 Seconds_Behind_Source（或 SHOW REPLICA STATUS），超阈值告警。
  2. 自动摘除：延迟超阈值自动把从库从读写分离移除，读全部回主库。
  3. 自动恢复：延迟降回后自动重新挂载，避免人工干预。
  4. 摘除策略：可配置（延迟超阈值摘除 N 分钟 / 连续 N 次超阈值才摘除，防抖动）。
  5. 监控指标：延迟秒数、摘除次数、从库健康度，接入告警平台。
  6. 注：Seconds_Behind_Source 只在有复制流量时体现延迟，静态无写时为 0。

六、踩坑记录（延迟不显示）

最初 simulate 只设 SOURCE_DELAY 但无写流量，Seconds_Behind_Source=0（无事件待应用）。需往主库写数据制造复制流量，并等待延迟累计，延迟才真实体现（实测设置10s、等待约7s后延迟显示7s）。

七、要点速览

主从延迟告警与从库自动摘除：读写分离下从库延迟会导致读过期数据。实测模拟延迟10s，Seconds_Behind_Source 累计到7s，超过阈值5s后自动摘除从库（读全部回主库），恢复后自动重新挂载。要点：监控 Seconds_Behind_Source、超阈值告警+摘除、恢复自动挂载；注意延迟只在有复制流量时体现。
