# ES7.17 写入全流程+**底层存储算法精准拆解**

从路由分片 → 日志存储 → 内存索引 → 磁盘段文件 → 词条排序 → 数据压缩，**每一步用什么算法、数据结构、存储格式**全部讲透

## 一、分片路由：数据分到哪个节点【分片分配算法】

### 1. 路由哈希算法

**算法：MurmurHash3（128位变体）**
源码位置：`Murmur3.java`

```java
int hash = Murmur3.hash128(routingKey);
int shardId = Math.abs(hash) % 主分片数量;
```

- 特点：低碰撞、高速运算、均匀散列
- 默认路由键 = 文档`_id`
- 结果：同ID文档**永远固定落在同一个主分片**
- 主分片数一旦创建不可修改，路由永久固定
  
  ### 2. 分片节点分配算法
  
  **算法：分片感知+权重轮询分配**
  集群分配策略：
1. 优先同机架、同机房就近分配
2. 磁盘使用率权重均衡
3. 主副分片强制不同节点防宕机
4. 新版：**自适应分片均衡算法**，自动平衡节点数据量

## 二、写入第一步：Translog 事务日志存储【落盘日志算法】

### 1. Translog 存储结构

- 存储文件：`.translog` 二进制顺序日志
- 数据结构：**顺序追加写（Append-Only）**
- 写入模式：**WAL预写日志机制**
  
  ### 2. 日志编码存储算法
1. **序列化算法**
   ES内部自定义二进制序列化：`StreamOutput`
   不使用JSON、不使用protobuf，自研紧凑二进制格式
   字段长度+字段类型+字段值 紧凑拼接
2. **刷盘持久化算法**
   - `request`策略：**fsync强制刷盘**，调用操作系统内核缓冲区落盘
   - `async`策略：**页缓存延迟刷盘**，内核定时回写磁盘
3. 日志删除机制
   触发`flush`后，旧translog文件**批量删除**，采用**版本号轮转清理算法**
   
   ### 3. 作用算法逻辑
   
   宕机恢复：**顺序回放算法**
   重启后从最后一次flush位置，从头顺序读取translog重做写入，恢复内存数据

## 三、写入第二步：内存缓冲区存储【内存索引结构+算法】

### 1. 内存缓冲区结构

底层由 **Lucene 内存索引缓冲区** 实现
核心数据结构：

1. **字节数组缓冲池（Recycler 池化复用算法）**
   复用内存块，减少GC，提升写入吞吐
2. **字段域内存哈希表**：快速按字段名存取字段值
   
   ### 2. 文档字段存储内存算法
- 数值类型：**原生8/4/2字节定长存储**（long/double/int）
- 字符串未分词：**UTF-8 紧凑编码**
- 分词文本：先分词，再存入**词条临时哈希表**
  
  ### 3. 并发写入控制算法
  
  **分段锁 + 内存块隔离算法**
  同一个分片多线程写入：按文档ID哈希分段加锁，提升并发写入能力

## 四、Refresh 刷新阶段【最核心：倒排索引构建+排序算法】

### 1. 分词使用算法

- 标准分词：**Unicode断词算法**
- IK分词：**正向最大匹配分词算法**
  从左到右最长优先匹配词典分词
  
  ### 2. 词条Term存储结构
  
  构建两大核心结构：
1. **词典（Term Dictionary）**
2. **倒排链表（Posting List）**
   
   ### 3. 词条全局排序【必考精准算法】
   
   **排序算法：快速排序 + 归并排序混合**
   **排序规则：Unicode 码点字典升序**
   执行时机：Refresh生成Segment瞬间全局排序
   排序目的：
   有序词典支持**二分查找算法**快速检索词条，这是ES查询快的根本
   
   ### 4. 词典压缩存储算法（内存+磁盘通用）
3. **FST 有限状态机压缩算法（最核心）**
   全称：Finite State Transducer
   作用：海量词条极致压缩，几十GB词条压缩至几GB
   ES/Lucene词典**唯一核心存储算法**
4. **前缀差分压缩算法**
   相邻词条相同前缀只存一次，大幅节省空间
   
   ### 5. 倒排链表存储算法
5. **增量编码（Delta-Gap 差值压缩）**
   文档ID连续时只存差值，不存完整ID
6. **FOR 帧单值压缩算法**
   数值型docId高密度压缩
7. **位压缩 BitPacking**
   极小整数用比特位打包存储

---

## 五、Flush 阶段：内存Segment → 磁盘持久化【磁盘文件存储算法】

### 1. 磁盘Segment 六大核心文件+对应存储算法

1. `.tim` 词条字典文件
   存储算法：**FST有限状态机 + 前缀压缩**
2. `.tip` 词条索引文件
   存储算法：**二分查找索引结构**，加速定位tim词条
3. `.doc` 倒排文档链表
   存储算法：**Delta差值压缩 + FOR整数压缩**
4. `.pos` 分词位置偏移
   存储算法：**变长整数VInt压缩**
5. `.pay` 权重、分值、负载信息
   存储算法：**浮点量化压缩**
6. `.fdt .fdx` 正向索引（原始文档内容）
   - fdx：文档偏移索引 → **有序数组二分查找**
   - fdt：文档内容 → **LZ4高速压缩算法**
     
     ### 2. 磁盘写入落盘算法
     
     **顺序批量落盘算法**
     一次性将整个内存Segment顺序写入磁盘，**随机IO极少**，写入速度极高
     
     ### 3. 文档原始内容压缩算法
     
     **全局默认压缩：LZ4 无损高速压缩**
     优势：压缩快、解压更快，读写性能均衡
     可修改为：Deflate高压缩率（慢）

---

## 六、后台段合并 Merge 阶段【合并重排+清理算法】

### 1. 小段筛选算法

**大小比例筛选策略**
自动识别体积差距小的小Segment进行合并

### 2. 合并内部重排两大算法

1. **词条全局归并排序算法**
   多个小段有序词条 → 合并为全局有序大词条字典
2. **文档ID归并有序重排**
   让大Segment内部文档ID连续有序，提升正向索引读取效率
   
   ### 3. 逻辑删除清理算法
   
   **墓碑标记清除算法**
   合并时扫描`.del`删除标记，直接剔除已删除文档，实现**物理删除**
   
   ### 4. 合并限流控制算法
   
   **令牌桶流量控制算法**
   限制每秒合并IO速度，避免业务高峰期磁盘打满

## 七、不同字段类型专属存储算法（精准区分）

1. **keyword 精准字符串**
   存储：完整UTF-8 + 有序排序 + FST压缩
   支持：聚合、分组、排序、精确查询
2. **text 分词文本**
   存储：分词后Term + 倒排链表 + 位置偏移
   算法：IK最大匹配分词 + FST词典压缩
3. **数值类型 long/int/double**
   存储：定长二进制 + 增量差值压缩
   算法：区间二分索引，快速范围查询
4. **日期 date**
   存储：转为**毫秒时间戳long类型**存储
   复用数值所有压缩与检索算法
5. **地理坐标 geo_point**
   存储：经纬度编码为**哈希网格算法**存储
   支持地理位置快速范围筛选

---

## 八、写入全程算法执行顺序（一字不差背诵版）

1. 文档ID经过 **MurmurHash3哈希算法** 计算分片
2. 主分片优先通过 **WAL预写日志** 写入translog（自研二进制序列化）
3. 数据写入JVM内存缓冲区，使用**池化内存复用算法**
4. 定时1s执行Refresh
   - 文本执行**正向最大匹配分词**
   - 词条执行**快速排序+Unicode字典升序**
   - 词条存入**FST有限状态机压缩词典**
   - 倒排链表启用**Delta差值压缩**
5. 达到阈值执行Flush
   - 内存Segment通过**LZ4压缩算法**持久化磁盘
   - 生成tim/tip/doc/fdt等结构化索引文件
   - 旧事务日志执行**版本轮转删除算法**
6. 后台定时执行Segment合并
   - 采用**归并排序**全局重排词条与文档
   - 用**墓碑清除算法**物理删除无效数据
   - **令牌桶算法**限制合并IO流量

## 九、核心面试精准问答（算法版）

1. ES分片路由用什么哈希算法？
   **MurmurHash3**
2. 词条排序用什么算法、什么规则？
   **混合快排+归并排序，Unicode字典升序**
3. 海量词条靠什么算法压缩？
   **FST有限状态机压缩**
4. 倒排docId用什么压缩？
   **Delta-Gap差值压缩 + FOR整数压缩**
5. 文档落地磁盘用什么压缩？
   **默认 LZ4 高速无损压缩**
6. 写入顺序：先内存还是先磁盘？
   **先磁盘WAL事务日志，再内存索引**
7. Refresh阶段核心完成哪两个算法动作？
