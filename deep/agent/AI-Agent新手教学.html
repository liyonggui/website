AI Agent 新手教学（后端工程师·零基础版）

2026-09-20agent 系列约 20 分钟阅读AI AgentSpring AI

你是谁：会写后端、懂接口/并发/缓存，但从没碰过 AI Agent。 这份文档怎么读：从上到下，每一课 = 一个概念 + 你项目里的代码 + 你现在动手试什么。别跳，前 5 课是地基。 你的实验室：Agent 项目根目录（phase1~6 都是我给你搭好的、能跑的）。

第 0 课：一句话建立正确的心智模型（最重要）

AI Agent 不是魔法。把它拆成你熟的东西：

  • 大模型（LLM）= 一个"很聪明但不靠谱的外部 HTTP 服务"。你 POST 一段文字进去，它返回一段文字。特点：
  • 无状态：它不记得你上一句说了什么（每次都要把历史重新发给它）；
  • 会胡说：它优化的是"像不像合理的下一句话"，不是"真不真"，所以会一本正经地编数据（术语叫幻觉 hallucination）；
  • 按 token 计费、有延迟：token≈字词的碎片，输入输出都算钱、都要时间。
  • Agent = 围绕这个不靠谱服务写的一个"编排服务"。它的全部工作就是：决定往这个服务的输入里塞什么、把它吐出来的东西怎么处理、要不要再调一次。

类比：LLM 就像一个"能力很强但爱吹牛、记性为零、按次收费的外部 API"。Agent 工程 = 你怎么把这个 API 用得靠谱。你过去治理"不靠谱下游服务"的那套（超时/重试/降级/缓存/对账/监控）全部适用。

记住三句话，后面每一课都在展开它： 1. 上下文窗口 = 模型唯一的"内存"； 2. token = 模型唯一的"成本和带宽"； 3. 非确定性 = 你唯一的对手（同样的输入，输出可能不一样）。

第 1 课：第一次"调用模型"（phase1 前半）

概念：所谓调用模型，就是发一个 HTTP 请求，带上"提示词(prompt)"，拿回一段文本。 - 你项目里：phase1-minimal-agent 的 AgentController 里 chatClient.prompt().user(问题).call().content() 就是"问一句、答一句"。 - 关键参数：temperature（0=稳定可复现，越高越发散）；model（选哪个模型）。

动手：起 phase1，curl -X POST localhost:8080/api/agent/chat -d "你好"，看它回话。再 curl -N ".../stream?text=..." 看流式（字一个个吐，因为模型是逐 token 生成的）。

新手误区：以为"模型记住了刚才的对话"。不——除非你把历史重新发过去（这就是第 4 课的"记忆"）。

第 2 课：让模型"动手"——工具调用（Function Calling）（phase1 核心）

这是 Agent 的心脏，务必吃透。

概念：模型只会输出文字，它不能自己查数据库/调接口。所谓"工具调用"是一个配合： 1. 你在请求里附带一份"工具说明书"：有哪些工具、叫什么名、参数是什么（JSON Schema）； 2. 模型看完问题，如果觉得"我该用工具"，它不返回人话，而是返回一个结构化意图：我要调用 searchSchools，参数 {city:"北京"}； 3. 你的代码（框架）看到这个意图，去真正执行那个方法，拿到结果； 4. 把结果塞回对话再发给模型； 5. 模型这次基于结果，给出人话答案（或再要下一个工具）。

所以"自主"= 上面 2→3→4→5 这个循环（模型说要调→框架调→结果回填→模型再想→…→不再要工具就停）。智能来自"模型会规划下一步"，能力来自"框架真的去执行"。

你项目里：phase1 的 DemoTools 里 @Tool 注解的方法（calculator、orderStatus）。@Tool 的 description 是写给模型看的说明书——写得越清楚，模型越会在对的时候、传对的参数去调它。这是新手最容易忽略、却最影响效果的点。

动手：curl -X POST localhost:8080/api/agent/chat -d "先算(128+64)*3，再查订单A1001"。看它连调两个工具再汇总——这就是多步自主。

新手误区： - 以为模型"执行"了工具。没有，执行的是你的框架；模型只是"点菜"。 - 工具返回值别原样丢一大坨 JSON 回去——每多一个字都是 token 成本、还会干扰模型。要裁剪（你项目里就只留关键字段、最多 8 条）。

第 3 课：给模型"外挂知识"——RAG（phase2）

问题：模型不知道你私有的资料（你的文档、你的业务数据），而且它会编。 解法 RAG（检索增强生成）：回答前，先去你自己的资料库里搜出相关的几段，塞进 prompt，告诉模型"只根据这些资料回答"。

概念拆解： - Embedding（向量化）：用一个模型把任意文本变成一串数字（向量，如 1024 维）。意思相近 → 向量距离近。于是"找相关资料"变成"算哪几段向量离问题最近"。 - 向量库：存这些向量、能快速找最近的。你项目用 SimpleVectorStore（内存版，够学习用）。 - 分块(chunk)：长文档要切成小段分别存。切太大→噪声多，切太碎→语义断。这是 RAG 效果的第一杠杆。 - 检索→拼上下文→约束作答：搜出 Top-K 段 → 拼进 prompt → 让模型只依据它回答，并标注引用（能溯源=防幻觉）。

你项目里：phase2-rag，语料在 src/main/resources/kb/*.md，启动时自动切分+向量化入库；/api/rag/ask?q=... 问答并带 (资料N) 引用。

动手：起 phase2，curl -G localhost:8082/api/rag/ask --data-urlencode "q@问题.txt"（注意：中文要走 UTF-8 文件，见第 8 课坑）。看答案 + 引用来源。

新手误区：以为 RAG 是"把整个文档库塞进 prompt"——不是，是检索出最相关的几段再塞（上下文有限、token 贵）。

第 4 课：多轮对话——"记忆"（phase3）

概念：模型无状态。所谓"记住上文"，是框架把之前的对话历史，每轮重新拼进 prompt 发给模型。 - 最简单：滑动窗口，保留最近 N 轮（你项目 MessageWindowChatMemory(20)）。 - 代价：历史越长，token 越多、越贵越慢，且太长模型会"注意力涣散"。所以有摘要、向量长期记忆等进阶手段（现在先知道有这回事）。

你项目里：phase3-agent 的 /api/a3/chat?cid=会话id&q=...，同一个 cid 就能追问。

动手：先问"北京前三院校"，同一 cid 再问"那上海的呢"——它没让你重复，说明记住了。

新手误区：把"记忆"想成数据库存东西。它本质是"每次重新发历史"，是成本，不是免费的。

第 5 课：接你自己的真实业务（phase3）

前面工具都是假的（计算器、假订单）。这一课把工具接到你真实的后端接口上——这才是 Agent 有生产价值的地方。 - 做法：把"查院校/查专业/查课程"这些真实 HTTP 接口，包成 @Tool 方法（方法内部用 HTTP 客户端调你的后端）。 - 你项目里：phase3-agent 的 SchoolTools 调 http://127.0.0.1/wxma/school 等（自研后端，跑在沙盒）。模型问"北京前三院校"，它真的去查你的库拿真数据。 - 关键纪律：Agent 只连本机后端，永不默认打生产。

动手：起后端+phase3，问一个只有你库里才有的事实（如某校软科排名），看它是不是真查出来的。

第 6 课：MCP——把"工具"标准化、解耦（phase5）

问题：第 5 课的工具是写死在 Agent 代码里的。加个工具就得改代码、重编译；换个 Agent 又得重写。 MCP（Model Context Protocol）= 给"工具"定一个通用协议（类比：USB-C）。工具提供方做成一个 MCP Server 对外声明"我有哪些工具"；Agent 作为 MCP Client 运行时动态发现并调用，不写死。 - 你项目里：phase5-mcp-server 把 /wxma 那几个接口封成 MCP 工具；phase5-mcp-client 那个 Agent 启动时通过 tools/list 自动拿到工具清单。 - 传输：本地用 stdio，网络用 streamable-http（一个 /mcp 端点 + 会话 id）。

动手：起 server(8085)+client(8086)，问一句，看 client 日志里工具是"从 MCP 发现的"而不是代码里写死的。

新手误区：一上来就上微服务/多 agent。先单 agent + 好工具 + 好评测，MCP 是"解耦工具"的手段，不是必须。

第 7 课：让它"能扛"——工程化护栏（phase4）

模型和下游都不靠谱，Agent 要能稳定扛住流量。全是你熟的后端套路： - 超时 + 降级：调下游设超时；下游挂了要快速失败并返回"不可用"，让模型如实说"查不到"，而不是瞎编。 - 舱壁（并发上限）：限制同时打模型的请求数（信号量），超了直接快速拒绝(503)——保护付费模型和线程。 - 熔断：下游连续失败就暂停一段时间，别一直撞墙。 - 缓存：重复的查询直接返回，把下游移出热路径（你项目实测 p95 从 836ms 降到 12ms）。 - 可观测：每次调用的延迟、token 用量、成本、工具成功/失败都要能看见（否则 Agent 是黑盒）。

你项目里：phase4-agent-ops（ToolGateway 缓存+熔断、AgentService 舱壁、AgentMetrics 指标、k6 压测脚本）。

动手：起 phase4，curl localhost:8084/api/ops/snapshot 看延迟/成本/工具计数；把工具基址指个死端口，看它怎么优雅降级。

第 8 课：怎么知道它"好不好"——评测（phase6，最值钱的一课）

为什么难：Agent 输出非确定、没有标准答案。跑一次"感觉挺对"不算数。 做法：造一批"带标准答案的测试题"，每次改动都自动跑分。几种打分方式，各有适用： - 关键词硬校验：答案里有没有关键事实（简单、可回归）； - LLM-as-judge：让另一个模型当裁判打分（能判"部分正确/幻觉"，但裁判自己也会错、会抖）； - trajectory（轨迹评测）：看它到底调没调对工具、参数对不对——这是 Agent 专属、前两种测不出的（能抓"模型凭常识瞎答、根本没查库"）； - RAGAS 四指标：给 RAG 用的 faithfulness/relevancy/precision/recall。 两条铁律（新手最该记住）： 1. 单次结果会抖 → 跑 N 次取中位数、看离散度，别拿一个百分比下结论； 2. 数字难看先怀疑"尺子"：是指标选错、还是裁判判错，还是系统真差——先归因再优化（我们踩过 precision@k 假象、裁判假阴性两次，都是"尺子错"）。

你项目里：phase6-eval（三路打分 + gate.sh CI 门禁，卡中位数阈值）。

动手：起全栈后 bash run-e2e-gate.sh，看它自动起服务→跑评测→中位数→门禁过/不过。

环境怎么起（你的实验室）

  • 一键起全栈 + 跑评测门禁：bash run-e2e-gate.sh
  • 逐接口怎么 curl、各服务端口：见项目 README.md（索引+手册）
  • 数据从哪来、代码链路：见 全链路.md
  • ⚠️ 两个必踩的坑先记住：① 模型 base-url 到 /compatible-mode（不带 /v1）；② Windows 的 Git Bash 里 curl 传中文会乱码，中文请求体一律写成 UTF-8 文件用 --data @文件。

建议学习顺序（新手）

第0课心智 → 第1课调用 → 第2课工具(心脏) → 第3课RAG → 第4课记忆 → 第5课接真实业务 → 第7课护栏 → 第6课MCP → 第8课评测。 每课都"起对应 phase、跑那条 curl、看结果"，动手 > 看字。

术语小抄（glossary）

  • LLM/大模型：文本进文本出的外部服务。
  • prompt/提示词：你发给模型的输入。
  • token：文本碎片，计费与长度单位。
  • temperature：输出随机度，0 最稳。
  • 幻觉 hallucination：模型一本正经编假内容。
  • Function/Tool Calling：模型输出"要调哪个工具+参数"，框架执行。
  • ReAct：边想(Reason)边做(Act)的循环范式。
  • Embedding/向量：文本→数字，语义近=距离近。
  • RAG：先检索再作答。
  • chunk/分块：文档切小段。
  • 向量库：存向量+近邻检索（HNSW/IVF 是加速索引）。
  • 上下文窗口：模型一次能看的最大长度=它的内存。
  • MCP：工具的通用协议（tools/list 发现、tools/call 调用）。
  • Agent：把上面这些编排起来、能自主多步完成任务的服务。
  • trajectory 评测：评它中间步（调没调对工具）而不只是最终答案。

第4课补充实验：用"指代词"肉眼验证记忆（强烈推荐亲手做）

给 /chat 加 memory 开关（读历史+写历史 或 完全脱离），然后对比： - a) cid=s1："查一下上海的院校"（memory=true）→ 答出列表 - b) cid=s1："那同济呢"（memory=true）→ 接上上文，答同济详情 ✓ - c) cid=s1："那同济呢"（memory=false）→ 也能答！因为"同济"在问题里，工具按名字查即可——注意这个坑：问题自带实体时，测不出记忆 - history 验证：s1 里只有 b 没有 c → memory=false 既不读也不写 ✓ - d) cid=s1："那它的学费"（memory=true）→ "它"=上文的同济 → 查出真学费 ✓ - e) 同句（memory=false）→ "它"无法解析 → 反问"哪所院校？" ✓ d/e 是决定性对比：指代词只能靠历史解析——有历史答、无历史问。这就是"上下文是框架拼的"的肉眼证据。

第7课补充实验：三道护栏的实测方法（已全跑通）

  • 舱壁：6 并发 /api/ops/chat（LLM并发上限=3）→ 3×503 秒拒 + 2×200（mean 11.8s）+1 客户端超时。拒得快、放行的变慢——并发保护的真实表现。
  • 缓存：/ops/snapshot 看 cache{} 命中计数；压测用 k6（cache-off/on 对比 p95 836→12ms，见 phase4 README）。
  • 熔断：混沌实例（工具基址指死端口+TOOL_TIMEOUT_MS=1000）连打 15 次 → 前 5 次真试失败 → OPEN → 之后 11 次 circuit-open 秒拒，返回 {"unavailable":true}。
  • 全部数字在 /ops/snapshot：延迟 mean/max、工具 ok/fail、cache hit/miss、breaker.rejects、token 成本。

第5/6课补充实验：复合问题全链路耗时拆解（phase5）

问"中大排名第几？在哪个省？有什么学院？有什么专业？"（cid=zd，总耗时 42.8s）： - 轨迹：2 次工具调用 search_schools(44ms) + search_majors(46ms)，工具链路合计 ~90ms（占 0.2%）； - 其余 42.7s 全是 3 轮 LLM 推理（占 99.8%）——优化 Agent 延迟先数"转了几轮 LLM"； - 模型自己把缩写"中大"解析成中山大学（⚠️ 歧义缩写有风险：中南大学也叫中大）； - "学院"没单独调 colleges 接口，从 search_majors 的 college_name 字段带出（省一次调用，但学院覆盖不全=只列有研究生专业的学院）——"省调用"vs"答得全"是业务取舍； - 同步 /chat 的首字节=总耗时（无流式）；要看首字延迟得用 /stream。

第6课补充实验：失控与修复的前后对比（必看）

问"中山大学有哪些学院？请尽量列全"——但 server 没暴露"列学院"工具： - 修复前：模型拿 search_majors 把能想到的专业关键词穷举了 100+ 次（计算机/医学/法学/外语/考古/口腔…），180s 超时无答案，成本爆炸； - 修复后（三处）：① server 补 list_colleges(schoolId) 工具（后端 /wxma/colleges 本来就有）；② client 的 RecordingToolCallback 加单次请求工具调用硬上限（超限返回"停止调用"指令让模型收敛）；③ 系统提示"查学院用 list_colleges 一次查全，禁止穷举"。 - 重跑同一问题：2 次工具调用（search_schools 133ms → list_colleges 79ms）、10.6s 出完整学院列表 20+ 个。 三条铁律：Agent 的能力边界 = 工具清单（缺能力它就硬凑）；循环必须有上限（开放式指令+无上限=成本失控）；这种失控只有 trajectory 能发现（终答评测可能还显示"正确"）。

第5/6课补充实验：不存在的大学（防幻觉测试）

问"亚特兰蒂斯大学排名第几？有哪些学院？"： - 轨迹：先调 search_schools(name=亚特兰蒂斯) → 29ms 返回空； - 回答：如实说"该院校不存在于数据库中"，未编造任何排名/省份/学院 ✓（防幻觉核心成立）； - ⚠️ 细节：它顺带补充了"亚特兰蒂斯是柏拉图传说中的文明"等常识背景——来自模型知识而非工具。教育场景无害，严格业务场景（金融/医疗）应约束"非工具来源的陈述一律不说"——常识补充是幻觉的温床，这次对不保证下次对。
