# 瑞达星 × Agent 全链路（代码级）

> 谁接入谁：**只有瑞达星后端 `/wxma` 被 Agent 接入**（读的是"择校/专业/课程"公开浏览接口）。
> 数据源纪律：Agent 打的是**沙盒后端** `D:\ai-agent-project\rdx-bx-backend`（本机 `127.0.0.1/wxma`），**永不默认生产** `www.ruidaxing.com.cn`。

## 一、涉及的仓库/工程

| 角色 | 路径 | 在本链路里干什么 |
|---|---|---|
| 瑞达星后端(原仓) | `D:\rdx-bx-backend` | **不碰** |
| 瑞达星后端(沙盒) | `D:\ai-agent-project\rdx-bx-backend` | Agent 的数据源；`java -jar target/blade-api.jar --spring.profiles.active=dev` 占 80 |
| 瑞达星官网 | `D:\rdx-website` | 仅**接口契约来源**(`src/utils/{request,school,major,course}.js`, BASE_URL `/api/wxma/`)；Agent 不经过它 |
| 小程序 | `D:\ruidaxing-mini-program` | 后端另一消费者，同理不被 Agent 调 |
| 管理端 / 考试系统 | `rdx-bx-frontend` / `rdx-exam-system` | **未涉及** |
| Agent | `D:\ai-agent-project\phase3-agent / phase4-agent-ops / phase5-mcp-server / phase5-mcp-client` | 消费 `/wxma`（phase3/4 直连、phase5 经 MCP） |

## 二、后端侧代码链（沙盒，真类名/方法/缓存键）

Base：`org.springblade.rdx.normal.wx` 下控制器，`@RequestMapping("/wxma")`。

- `GET /wxma/school?page,city,name,way,level,major`
  → `WxMaSchoolController.getSchool(...)`
  → `WxQueryCache.school(RdxCacheKey.SCHOOL, ...)`（两级缓存：本地 + Redis，未命中回源）
  → `IWxMaSchoolService` → MyBatis-Plus Mapper → **MySQL `rdx_school`**
  → 返回 `R<IPage<Map>>` = `{code,success,data:{records,total,pages,size,current},msg}`
- `GET /wxma/majors/search?page,pageSize,school,region,major,direction,subject,learningStyle`
  → `WxMaSchoolController.searchMajors(...)` → `WxQueryCache.majorsSearch(RdxCacheKey.MAJORS_SEARCH)`（JOIN 院校）→ Service → Mapper → MySQL
- `GET /wxma/course?type,category`
  → `WxMaCourseController.getCourse(...)` → `WxQueryCache.course(RdxCacheKey.COURSE_LIST, () -> courseService.getCoursesByType(type,category))` → Mapper → MySQL
  → 返回 `R<List<RdxCourse>>`（注意：course 的 `data` 是**数组**、非分页 `records`）

鉴权：上面 3 个是**匿名可访**（走 WxQueryCache，无 token）；`/wxma/majors/count` 才 `WxMaJwtUtil.validateToken`。这解释了 Agent 不需要登录态。

## 三、Agent 侧两条等价路径（同一 `/wxma`，两种接线）

### 路径 A：phase3/4 — 本地硬编码 @Tool
```
HTTP 用户 /api/a3/chat?cid&q (phase3) 或 /api/ops/... (phase4)
  → ChatClient(defaultTools = RuidaxingTools / ToolGateway包一层)
  → 模型出 tool_calls → Spring AI 反射执行 @Tool searchSchools(name,city,page)
     [phase4: ToolGateway = Caffeine缓存 + Breaker熔断 + RestClient超时/降级 → 返回结构化unavailable]
  → RestClient(baseUrl=http://127.0.0.1/wxma).GET /school → (第二节后端链) → JSON
  → pick() 裁字段+Top-8 → 作为 tool 结果回填 → 模型 → 答案
  → phase3 还叠 MessageChatMemoryAdvisor(cid 多轮记忆) + /stream SSE
```

### 路径 B：phase5 — MCP 动态发现（工具与 Agent 解耦）
```
phase5-mcp-client  /api/a5/chat?cid&q
  → ChatClient(defaultToolCallbacks = MCP ToolCallbackProvider 的回调, 各包 RecordingToolCallback 记 trajectory)
  → 模型出 tool_calls → MCP client 经 streamable-http 发 JSON-RPC tools/call
     端点 http://localhost:8085/mcp（握手 initialize→Mcp-Session-Id→…）
  → phase5-mcp-server: RdxTools @Tool(search_schools/search_majors/list_courses) 由 MethodToolCallbackProvider 发布
  → RestClient(http://127.0.0.1/wxma).GET /school → (第二节后端链) → JSON 裁剪 → tool 结果 → 回填 → 模型答
```
即：**"哪些工具、参数是什么"从 phase3 的代码里，搬到了 phase5-mcp-server 的协议里**；client 只 `tools/list` 发现，不写死。

### 消费方
- phase6-eval：用 RestClient 打 `phase5-mcp-client:/api/a5/chat` + `/api/a5/trace`，做关键词/judge/**trajectory** 评测，`gate.sh` 卡 CI 门禁（下一步可加 runs 中位数）。

## 四、一张时序图（一次 phase5 全链问答）
```
用户 →(HTTP /api/a5/chat cid,q) phase5-mcp-client
      →(LLM 请求含 tools schema) 百炼MaaS kimi
      ←(tool_calls search_schools{city:北京}) 
      →(MCP tools/call, HTTP /mcp + Mcp-Session-Id) phase5-mcp-server
      →(RestClient GET /wxma/school?city=北京) 沙盒后端
      →(WxMaSchoolController→WxQueryCache[Redis]→Service→Mapper→MySQL)
      ←(R<IPage> JSON)→ 裁字段Top8 →(MCP tool结果)→ 回填
      →(再请求 MaaS)  kimi 生成带事实答案
      ←(answer + tool轨迹存 RecordingToolCallback) 返回用户；/trace 可查轨迹；Langfuse 有 span
```

## 五、要点回顾（后端视角）
- 模型 = 不靠谱下游；工具/检索 = 给它外挂能力；`/wxma` = 唯一真实业务数据源；
- phase3 vs phase5 = 写死 @Tool vs MCP 动态发现（演进对照，面试素材）；
- phase4 的缓存/熔断/舱壁、phase5 的 MCP、phase6 的评测——全是把"能跑"做到"能扛、能量化"。
