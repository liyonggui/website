Phase 6 · 评测

给 Agent 建评测体系：关键词硬校验 + LLM-as-judge 双维度 harness，CI 门禁任一维度通过率 < 90% 即失败。8087 · 关键词 100% / 裁判均分 1.8

项目概述

评测 harness 两层：关键词硬校验（答案必须包含指定事实，不信任模型自由发挥）+ LLM-as-judge（裁判模型按 rubric 打分，均分 1.8/2）。两层各有通过率，CI 里任一维度 < 90% 直接失败。

这让 Agent 的每次改动都有回归兜底：换模型、改 prompt、调检索参数，跑一遍评测集就知道有没有退化，而不是上线后靠用户反馈发现。

技术亮点与难点攻坚

  • Agent 改动无法回归难点：换模型、改 prompt、调检索参数都可能悄悄变差，人工抽查覆盖不了长尾。方案：建评测 harness：关键词硬校验（事实必须命中，实测 100%）+ LLM-as-judge 按 rubric 打分（均分 1.8/2），每次改动跑全集出报告。
  • 评测分数「看着不错」却不设防难点：评测只出数字不卡发布，退化照样上线。方案：接入 CI 门禁：任一维度通过率 < 90% 直接 fail，评测从「参考指标」升级为「发布门槛」，质量门禁实践另见工程实战复盘。
  • 裁判模型自身不可靠难点：LLM-as-judge 的打分随模型与 prompt 波动，单次评分不足为凭。方案：rubric 明确评分维度与扣分点，裁判 prompt 版本化管理，分数分布而非单次分值作为结论依据。

关键数据与亮点

  • 双维度评测关键词硬校验 100% + LLM 裁判均分 1.8/2
  • CI 门禁任一维度通过率 < 90% 即失败，防回归
