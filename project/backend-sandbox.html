业务后端沙盒

为 Agent 系列准备的业务后端沙盒（可修改副本，原仓不碰）：作为 Agent 业务工具的被测后端与基础设施来源。端口 80

项目概述

Agent 开发需要一个「可以随便折腾」的业务后端：真实接口、真实数据、但改坏了不心疼。沙盒从业务仓复制而来，独立运行在 80 端口，Phase 3 起的所有业务 @Tool 与 Phase 5 的 MCP Server 都以它为数据源。

「可改，原仓不碰」是刻意的工程边界：沙盒允许为了测试护栏、异常注入而改造接口行为（比如模拟慢查询、限流），原仓保持干净可同步。

技术亮点与难点攻坚

  • 测试环境「不敢破坏」难点：Agent 护栏需要模拟慢查询、限流、异常注入，直接改业务仓既危险又污染历史。方案：复制出独立沙盒（可改，原仓不碰）：为验证目的自由改造接口行为，用完即弃，原仓保持可同步的干净状态。
  • 异常注入如何逼近真实故障难点：随手抛异常测不出真实故障模式（超时、半开、部分成功）。方案：按故障类型实现注入点：延迟注入（模拟慢查询）、限流注入、部分成功响应，让 Phase 4 舱壁/熔断在可控故障下完成实测。
  • 沙盒与原仓的配置漂移难点：沙盒改久了接口契约漂移，Agent 工具定义对不上。方案：以沙盒接口为准生成工具 schema，原仓同步时跑契约校验，漂移即报警。

关键数据与亮点

  • 被测后端Agent 业务工具的真实数据源
  • 可破坏性支持异常注入改造（慢查询/限流模拟），原仓不受影响
