Agent 产品层

六阶段能力的集大成：rag_search（向量 + BM25 + RRF + rerank）+ MCP 业务工具 + Redis 三件套（向量/缓存/记忆）+ resilience4j + Langfuse 评测 + 鉴权脱敏。8090 · gold 13/13

项目概述

产品层把前面所有阶段拼成一个可交付系统：检索侧向量 + BM25 双路召回 RRF 融合再 rerank；工具侧走 MCP 动态发现；Redis 同时承担向量库、语义缓存与会话记忆；中间件用 resilience4j 收拢护栏。

质量与安全两侧：Langfuse 全链路评测（gold 集 13/13 通过），语义缓存带维度一致性护栏（实测拦截 guardRejects=1，防止错缓存串答案）；入口鉴权 + 敏感信息脱敏。

技术亮点与难点攻坚

  • 双路召回的融合顺序难点：向量与 BM25 各有强项，简单拼接互相当噪音，加权又难调。方案：RRF（倒数排名融合）做无参融合再统一 rerank，实测排序稳定性优于线性加权；gold 集 13/13 通过。
  • 语义缓存的「错误命中」难点：问题语义相近但业务维度不同（城市/日期），缓存命中反而返回错误答案。方案：缓存命中前做维度一致性护栏校验，实测拦截 1 次（guardRejects=1）——宁可回源也不返回错答案，护栏与收益并行。
  • Redis 三种角色的资源争抢难点：向量库、语义缓存、会话记忆共用 Redis，大 value 与热 key 互相挤兑。方案：按角色分库/分前缀隔离，分别设置 TTL 与淘汰策略，内存水位与命中率分指标监控。
  • 评测与可观测的两张网难点：问题要么靠评测集在发布前拦住，要么靠线上观测在运行时发现，二者缺一都会漏。方案：Langfuse 全链路追踪（每次调用的检索/工具/token）+ gold 集回归，发布前与运行时双保险，入口鉴权与敏感信息脱敏兜底安全侧。

关键数据与亮点

  • gold 集 13/13评测集全通过
  • 语义缓存护栏维度一致性校验，实测拦截 1 次错缓存
  • 安全侧入口鉴权 + 敏感信息脱敏
