Phase 2 · RAG

在最小 Agent 上加检索增强：embedding + 向量库 + 带引用问答 + 召回评测，召回率实测 83%。8082 · 召回 83%

项目概述

实现走的是可解释路线：Spring AI 的 EmbeddingModel + Document 分层 + SimpleVectorStore 起步，再对比混合检索（向量 + BM25）与 rerank 的增益。每一步的召回率都可量化，不是「感觉变好了」。

带引用问答是硬要求：答案必须标注来源文档，评测集单独维护，召回率 83% 是在这套评测集上跑出来的可复现数字。

技术亮点与难点攻坚

  • 召回率不可量化难点：「检索效果好像变好了」的表述无法指导优化方向，改一版 prompt 就可能悄悄退化。方案：先建评测集再谈优化：固定问题集 + 标准答案来源，召回率逐版统计，83% 是这套评测集上的可复现数字。
  • 单路向量检索的召回上限难点：纯向量检索对术语类查询（型号、编号）召回差，语义近似但不精确命中。方案：混合检索：向量 + BM25 双路召回，RRF 融合排序再 rerank；分层实现（Document 切分策略与 SimpleVectorStore 起步）保证每一步增益可单独度量。
  • 模型一本正经编造来源难点：LLM 对检索不到的内容自行发挥，答案可信度无法追溯。方案：带引用问答硬约束：答案必须绑定来源文档片段，无来源不输出，评测时同时校验引用的正确性。

关键数据与亮点

  • 召回率 83%评测集量化，非主观感受
  • 带引用问答答案强制标注来源，可追溯
  • 混合检索向量 + BM25 + rerank 的分层对比
