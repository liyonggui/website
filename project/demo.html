秒杀 Demo

可一键运行的秒杀库存压测 Demo：docker-compose 起全栈，自带 100–300 五档并发 benchmark HTML 报告与初始化数据。多档 benchmark 报告

项目概述

定位是「拿来就能跑」的压测样例：docker-compose 一键起 MySQL + Redis + 应用，init.sql 初始化库存与账号数据，脚本按 100/150/200/250/300 五档并发跑完自动出 HTML 报告。

Demo 同时是降级设计的试验田：Redis 预扣 + 本地文件兜底的库存方案，在 Redis 不可用时如何限速回放、如何保证最终一致，都在这个仓里可以直接看代码。

技术亮点与难点攻坚

  • 秒杀场景的库存一致性难点：高并发抢购下查了再扣必然超卖，纯 Redis 预扣又在宕机时丢数据。方案：Redis 原子预扣（Lua/DECR）作为主路径，本地文件兜底记录增量，恢复后限速回放对账，保证最终一致——降级链路全程可观测。
  • 压测环境搭建成本高难点：每次压测要手动起 MySQL/Redis/应用、灌数据、清状态，效率低且容易环境污染。方案：docker-compose 一键编排全栈，init.sql 幂等初始化，压完即弃、随起随测。
  • 报告不具备可复现性难点：压测报告只有结论没有环境与参数，换个人跑不出同样数据。方案：五档并发参数、场景脚本、init 数据全部入库，HTML 报告由脚本自动生成，任何人 clone 后可复现同组数据。

关键数据与亮点

  • 一键起环境docker-compose 编排 MySQL + Redis + 应用
  • 五档报告100–300 并发 benchmark HTML 报告开箱即用
  • 兜底方案Redis 预扣 + 本地文件兜底 + 限速回放
