Phase 3 · 业务 Agent

把 Agent 接上真实业务：真实业务接口当 @Tool、多轮对话记忆、SSE 流式交互，实测「查北京院校 → 追问上海」能正确走记忆。8083 · 多轮记忆

项目概述

这一阶段回答「Agent 怎么接真实业务」：把业务后端的查询接口封装成 @Tool，模型在多轮对话里自主决定何时调用、何时追问。记忆层负责把上下文里已确认的条件带到下一轮。

实测场景：第一轮查北京 1/2/11 三所院校，第二轮直接问「上海呢」，Agent 从记忆取上下文正确切换城市——这验证了记忆注入的时机与格式是对的。

技术亮点与难点攻坚

  • 记忆注入的时机与格式难点：全量塞上下文会爆 token，漏塞又答非所问——多轮记忆的边界不好拿捏。方案：按轮次维护结构化会话状态（已确认条件显式存储），推理时注入「当前有效条件」而非历史全文；实测追问场景（查北京后问上海）正确切换城市。
  • 真实业务接口当工具的不可控性难点：mock 工具无法暴露真实接口的参数歧义、慢响应与部分失败。方案：直接把业务后端查询接口注册为 @Tool，真实数据、真实延迟；配合 Phase 4 的舱壁与熔断兜住真实接口的不确定性。

关键数据与亮点

  • 真实业务工具业务接口直接注册为 @Tool，非 mock
  • 多轮记忆跨轮次上下文保持，追问实测通过
  • SSE 流式打字机式输出，交互不阻塞
