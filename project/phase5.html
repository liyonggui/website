Phase 5 · MCP

把业务接口封装成 MCP Server（streamable-http），Agent 改造为 MCP 客户端动态发现工具，从「硬编码工具」升级到「协议化工具」。8085/8086 · 真实取数

项目概述

Phase 3 的工具是编译期写死的 @Tool；这一阶段把工具协议化：业务后端封成 MCP Server，Agent 启动时动态发现工具列表，新增工具不需要改 Agent 代码。

实测链路走真实取数：/wxma 接口封装为 MCP 工具，Agent 通过 streamable-http 通道调用，返回真实数据。架构对比图见项目清单页（Phase 3 直连 vs Phase 5 MCP 动态发现）。

技术亮点与难点攻坚

  • 工具硬编码的扩展瓶颈难点：每接一个业务工具都要改 Agent 代码、重新发版，工具增长与发布节奏互相拖累。方案：工具协议化：业务后端封装为 MCP Server（streamable-http），Agent 作为 MCP 客户端启动时动态发现工具列表，新增工具零 Agent 改动。
  • MCP 通道的真实取数验证难点：协议跑通≠数据正确，需要验证参数传递、结果序列化在真实链路上不变形。方案：以 /wxma 业务接口为试点走通真实取数：参数 schema 校验、结果结构化回传、异常码透传三段都有实测记录（phase5 详解文档）。

关键数据与亮点

  • 工具协议化@Tool 硬编码 → MCP Server 动态发现
  • streamable-http标准协议通道，真实取数
