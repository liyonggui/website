Phase 1 · 最小 Agent

用最小代码量打通「模型调用工具 → 拿结果 → 再推理」的闭环：@Tool 工具注册 + 流式输出，不引入任何框架魔法。8080 · 实测 576+ 已发货

项目概述

这一阶段刻意做减法：一个 @Tool 注解的工具循环、一套 SSE 流式输出，验证 Spring AI 的工具调用链路到底需要哪些部件。576+ 单已发货的实测结果证明闭环可用。

价值在于建立了后续所有阶段的基准：之后的记忆、RAG、MCP、评测都是在「这个最小闭环还缺什么」的追问下一步步加出来的。

技术亮点与难点攻坚

  • 工具调用的最小闭环到底需要什么难点：框架文档琳琅满目，不清楚「模型→工具→结果→再推理」链路里哪些是必需件。方案：用 @Tool 注解注册业务函数，让 Spring AI 处理函数签名/参数 schema 的序列化与调用回传，最小代码跑通闭环并流式输出，576+ 单实测验证。
  • 流式与工具调用的冲突难点：流式输出希望 token 尽快吐出，而工具调用需要等完整结果才能继续推理，两者叠加时序容易乱。方案：区分「中间工具调用不外发」与「最终回答流式」两种阶段，SSE 通道只透传面向用户的增量，链路实测不卡顿。

关键数据与亮点

  • 最小闭环@Tool 工具循环 + 流式输出，零框架魔法
  • 实测验证576+ 单已发货，链路稳定
