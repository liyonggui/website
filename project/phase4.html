Phase 4 · Agent 运维

给 Agent 加生产护栏：可观测、降级、LLM 舱壁隔离、语义缓存、自研熔断，全部用 k6 压测验证过效果。8084 · 缓存 A/B p95 836→12ms

项目概述

四个护栏各有实测数据：LLM 舱壁隔离（信号量 6/s）在打满时 90% 请求 503 而不是拖垮全服务；语义缓存 A/B 实测 p95 从 836ms 降到 12ms（↓98.6%）；自研熔断在连续异常后 16 次快速拒绝；可观测埋点覆盖工具调用耗时与 token 消耗。

设计原则是「护栏不能比业务更脆弱」：降级路径、缓存维度一致性、熔断恢复都在故障注入里验证过，护栏代码与原理有逐行详解文档。

技术亮点与难点攻坚

  • LLM 接口一慢全链路跟着瘫难点：LLM 响应长尾严重，高并发下请求堆积把线程池占满，Agent 与非 LLM 功能一起不可用。方案：舱壁隔离：LLM 调用独立信号量（6/s），打满时快速失败（实测 90% 503）而非无限排队，主链路资源不被侵蚀；降级路径返回兜底话术。
  • 相同问题重复烧 token难点：高频问题每次都完整走「检索+推理」，延迟 836ms 且成本线性增长。方案：语义缓存 A/B 实测：命中时 p95 从 836ms 降到 12ms（↓98.6%）；缓存键做语义归一，并加维度一致性校验防止「看起来像、条件不同」的错误命中。
  • 依赖故障后的雪崩式重试难点：下游异常时客户端重试风暴放大故障，服务自愈被持续打断。方案：自研熔断：连续异常计数触发打开态，快速拒绝 16 次实测无穿透，半开态探活恢复；观测埋点覆盖工具耗时与 token 消耗，异常先于用户发现。

关键数据与亮点

  • 缓存 A/Bp95 836ms → 12ms，↓ 98.6%
  • 舱壁隔离信号量 6/s 打满时 90% 503，保护主链路
  • 自研熔断连续异常 16 次快速拒绝，防雪崩
